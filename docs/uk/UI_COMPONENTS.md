# Налаштування та компоненти керування Eta

Eta надає уніфіковані компоненти для налаштувань, списків керування та введення функцій на існуючому Miuix. Візуальний стиль використовує групування стилів ColorOS 17, відповідність кольорів значків, інтервали та керування пропорціями; Тема, безперервні заокруглені кути, анімація керування, дотик системи та життєвий цикл еластичного шару продовжують надаватися Miuix. Компонент не залежить від конкретного ПЗУ, а залежна версія залежить від конфігурації збірки проекту.

## Вибір компонентів

| Сцена | Компонент |
| --- | --- |
| Стандартна сторінка списку | `MiuixScaffoldPage`, підключено до `EtaPreferenceTheme` |
| Персоналізована сторінка або сторінка | `MiuixScaffold`, отримав доступ до тієї самої теми та широкоекранного скелета |
| Картка Контейнер | `EtaCard` |
| Встановити групування елементів, назву групи | `EtaPreferenceGroup`, `EtaPreferenceGroupTitle` |
| Картка, що складається з незалежних записів відкладеного завантаження | `EtaPreferenceGroupItem`, передайте фактичну першу та останню позицію |
| Повідомлення, статус або настроюваний текстовий рядок | `EtaPreference` |
| Лінії переходу, лінії перемикання | `EtaArrowPreference`, `EtaSwitchPreference` |
| Індивідуальний вбудований комутатор | `EtaSwitch`, повторно використовуйте той самий розмір елемента керування та поведінку Miuix |
| Окремий вибір, перевірений рядок | `EtaRadioButtonPreference`, `EtaCheckboxPreference` |
| Меню вибору в Scaffold | `EtaOverlayDropdownPreference` |
| Меню вибору шару вікна | `EtaWindowSpinnerPreference` |
| Потрібне повне меню вибору DropdownItem | `EtaDropdownPreference` |
| Розділова лінія вирівнювання значка та тексту | `EtaPreferenceIcon`, `EtaPreferenceDivider` |
| Піктограма, заголовок, вхід функції резюме | `EtaFeatureCard` |
| кнопка, рядок кнопок підтвердження | `EtaTextButton`, існуючий `MiuixDialogActions` |
| Діалогове вікно в шарі вікна або Scaffold | `EtaWindowDialog`, `EtaOverlayDialog` |

`EtaPreferenceDefaults`, `EtaCardDefaults` і `EtaControlDefaults` є джерелами істини для розмірів; `EtaPreferenceColors` керує кольорами піктограм категорії. Колір класифікації вибирається абонентом відповідно до функції, піктограма бренду зберігає вихідний колір, а помилки та інші запущені стани продовжують використовувати існуючу семантику стану.

## Групування та поля

За замовчуванням `EtaPreferenceGroup` має горизонтальні поля сторінки та інтервал у нижній групі. Коли `modifier` передається явно, абонент керує зовнішнім макетом; не накладайте набір стандартних полів знову і знову. Рядки, встановлені всередині картки, самостійно споживають заповнення, а блок форми споживає заповнення відповідно до власних вимог до вмісту.

```kotlin
EtaPreferenceGroupTitle("Підключення")
EtaPreferenceGroup {
    EtaArrowPreference(
        title = "Постачальник послуг",
        startAction = {
            EtaPreferenceIcon(icon = providerIcon, tint = EtaPreferenceColors.Blue)
        },
        onClick = onOpenProvider,
    )
    EtaPreferenceDivider()
    EtaSwitchPreference(
        title = "Увімкнути підключення",
        checked = enabled,
        onCheckedChange = onEnabledChange,
        startAction = {
            EtaPreferenceIcon(icon = connectionIcon, tint = EtaPreferenceColors.Blue)
        },
    )
}
```

Не забезпечуйте порожні слоти для піктограм для рядків без піктограм; використовуйте `hasLeading = false` для розділових ліній. Умовна лінія розміщується на тій самій видимій гілці, що й її попередня розділова лінія, і малюється лише за наявності попереднього елемента. Використовуйте окремі відкладені записи зі стабільними ключами та `EtaPreferenceGroupItem` для довгих списків. Не поміщайте модель або повний набір файлів у відкладений запис заради зовнішнього вигляду картки.

## Кнопки та спливаючі вікна



Діалогове вікно шару вікна та внутрішній спливаючий шар Scaffold зберігають відповідні механізми розміщення. Не розміщуйте `EtaOverlayDialog` у контексті, де відсутній Scaffold, і не замінюйте спливаюче вікно на Overlay для цілей стилю. У спливаючому вікні спільного доступу використовується колір поверхні картки теми, щоб відрізнити її від фону сторінки, і колір фону додаткової кнопки, щоб кнопка «Скасувати» не зливалася зі спливаючим вікном. Спільна інкапсуляція уніфікованих параметрів зовнішнього вигляду; логіка підтвердження, зворотні виклики скасування та довге прокручування вмісту все ще є відповідальністю абонента.

На сторінці налаштувань освітлення за замовчуванням використовується нейтральний фон, біла картка та синій акцентний колір; Моне та темні конфігурації відповідають темі програми. Теми сторінки налаштувань не замінюють текст чату, вміст терміналу та стилі веб-переглядача.

## Перевірка

`EtaPreferenceRenderingTest` Перевірте в справжньому дереві макета Compose, чи існують назви перемикачів, радіо та меню вибору, а також положення правого слота з піктограмами чи без них. Під час повторного використання елементів керування на сторінках слід продовжувати перевіряти вимкнені стани, умовні елементи, довгі підсумки, великі шрифти, вузькі екрани, методи введення та поведінку закриття спливаючих вікон.
